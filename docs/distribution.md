# Distribution

## What is published today

The package base (`@slice-soft/ss-stencil-web-components-lib`) ships two outputs:

| Output | Where | Contents |
|--------|-------|----------|
| **GitHub Packages** | npm registry | `dist/` + `loader/` |
| **CDN (Cloudflare R2)** | `cdn.slicesoft.dev/web-components/` | `loader/` + `dist/ss-stencil-web-components-lib/` |

Framework-specific wrappers (React, Angular, Vue) are **not generated yet**. See [Framework integrations](#framework-integrations) below.

---

## Consuming the base package

### From npm / GitHub Packages

```
npm install @slice-soft/ss-stencil-web-components-lib
```

Requires a `.npmrc` pointing to GitHub Packages:

```
@slice-soft:registry=https://npm.pkg.github.com
```

### JavaScript / HTML (CDN)

```html
<!-- Auto-registers all components, latest version -->
<script type="module"
  src="https://cdn.slicesoft.dev/web-components/latest/loader/cdn.js">
</script>

<!-- Pinned version -->
<script type="module"
  src="https://cdn.slicesoft.dev/web-components/v1.0.0/loader/cdn.js">
</script>

<ss-button>Click me</ss-button>
```

### JavaScript / HTML (npm package)

```js
import { defineCustomElements } from '@slice-soft/ss-stencil-web-components-lib/loader';
defineCustomElements();
```

### React (no wrapper yet — use loader directly)

```jsx
import { useEffect } from 'react';
import { defineCustomElements } from '@slice-soft/ss-stencil-web-components-lib/loader';

// Call once at app entry point
defineCustomElements();

// Use components as HTML elements
function App() {
  return <ss-button>Click me</ss-button>;
}
```

> TypeScript: add `declare namespace JSX` or use `as any` until the React wrapper package is published.

### Angular

```ts
// app.module.ts
import { CUSTOM_ELEMENTS_SCHEMA, NgModule } from '@angular/core';
import { defineCustomElements } from '@slice-soft/ss-stencil-web-components-lib/loader';

defineCustomElements();

@NgModule({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})
export class AppModule {}
```

### Vue

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [
    vue({
      template: {

  ],

```

```ts

defineCustomElements();
```

## Tree-shaking / lazy loading

Stencil's `dist` output loads component chunks lazily by default. The loader only fetches the JS for components actually used on the page.

For full tree-shaking at build time (no lazy loading), import from the `dist-custom-elements` output:

```js
import { SsButton } from '@slice-soft/ss-stencil-web-components-lib/dist/components';
```

## Framework integrations

### Current state

Framework wrappers are **deactivated**. The `reactOutputTarget` in `stencil.config.ts` is commented out because it writes to a sibling repository path (`../ss-stencil-web-components-lib-react/...`) that does not exist in CI. Generating wrappers this way is incompatible with isolated repo workflows.

### Planned approach

Each framework integration will be a separate published package with its own repository and release workflow:

| Package | Repo | Status |
|---------|------|--------|
| `@slice-soft/ss-stencil-web-components-lib` | `ss-stencil-web-components-lib` | ✅ Active |
| `@slice-soft/ss-stencil-web-components-lib-react` | `ss-stencil-web-components-lib-react` | 🔲 Planned |
| `@slice-soft/ss-stencil-web-components-lib-angular` | `ss-stencil-web-components-lib-angular` | 🔲 Planned |
| `@slice-soft/ss-stencil-web-components-lib-vue` | `ss-stencil-web-components-lib-vue` | 🔲 Planned |

Each wrapper package will be generated by a GitHub Actions workflow that:
1. Checks out both this repo and the wrapper repo
2. Runs `stencil build` with the appropriate output target
3. Commits and publishes the generated wrappers from the wrapper repo

This avoids local sibling path dependencies entirely.

## Release → Publish → CDN flow

```
push / merge to main
  │
  ▼
release-please (create-release.yml@v0)
  │
  ├── no release created → stop, nothing published
  │
  └── release_created == true
        │
        ▼
      build (inline job)
        ├── npm run build
        ├── artifact: npm-dist  (dist/ + loader/)
        └── artifact: cdn-dist  (loader/ + dist/ss-stencil-web-components-lib/)
              │
              ├── publish → publish-node-ghpkg.yml@v0 → GitHub Packages
              └── deploy-cdn → deploy-cdn-cloudflare.yml@v0 → cdn.slicesoft.dev/web-components/
```

CDN structure per release:

```
cdn.slicesoft.dev/web-components/
  v1.2.3/          ← immutable, max-age=1year
    loader/
      cdn.js
      index.js
      ...
    dist/ss-stencil-web-components-lib/
      ...chunks...
  latest/          ← max-age=1h, updated on each release
    loader/
    dist/ss-stencil-web-components-lib/
```

### Required GitHub repository secrets (for CDN)

| Secret | Description |
|--------|-------------|
| `R2_ACCESS_KEY_ID` | Cloudflare R2 access key |
| `R2_SECRET_ACCESS_KEY` | Cloudflare R2 secret key |
| `R2_ENDPOINT` | R2 S3-compatible endpoint URL |
| `R2_BUCKET` | R2 bucket name |
| `CDN_BASE_URL` | Public CDN base URL (e.g. `https://cdn.slicesoft.dev`) |

`GITHUB_TOKEN` is provided automatically by GitHub Actions.

> The release and publish flow runs only in GitHub Actions. There are no local publish or release scripts.
