# Component capacity (phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ss-input` icons and clear button, a clickable `ss-card`, and a new `ss-search-select` (+ `ss-option`).

**Architecture:** Component tokens first in ss-design-system (`tokens/components/*.json` → `--ss-<c>-*`), then the lib reads only its own tokens (`npm run lint:tokens` enforces it). Lib tests run against a committed DS copy refreshed by `npm run tokens:sync` from `../ss-design-system/dist/css`. The search select reuses the overlay layer (`anchorTo`, `onResize`, `onDismiss`, `rovingIndex`) and draws its list from data, as `ss-tabs` draws tabs from `ss-tab`.

**Tech Stack:** Stencil 4, SCSS (`@use '../../../global/styles/control' as c;`, `c.t(component, name)`), Jest spec + Puppeteer e2e, Style Dictionary (DS).

**Spec:** `docs/superpowers/specs/2026-11-24-component-capacity-design.md`

## Global Constraints

- The component only shows: no fetch, no debounce, no timers on `ssSearch`.
- Nothing changes for a consumer who does not opt in: wave-1 (`ss-input`) and wave-4 (`ss-card`) computed-style snapshots stay unchanged when the new props/slots are unused.
- No prop depends on `data-style`. Every new color/size/duration is a component token referencing system roles (`control.*`, `field.*`, `color.*`, `space.*`, `material.*`, `shape.*`, `layout.*`, `elevation.*`, `motion.*`).
- Accessibility asserted on the accessibility tree (`axNodeByRole`, `axNodeNamed` in `src/test/utils.ts`), never on attributes alone. Cross-shadow references through `utils/a11y` (element reflection).
- e2e pages via `newTestPage` + `useTokens`; `npm test` runs one worker.
- Default copy, translatable by prop: `clear-label="Clear"`, `loading-label="Loading…"`, `empty-label="No results"`, chip remove name `Remove <label>`.
- `readme.md` files are generated by the build; never edit them.
- Delivery: two DS+lib PR pairs (wave 1: Tasks 1–4; wave 2: Tasks 5–9). DS PR merges and releases first; lib PR bumps `test/tokens.config.json`.

## Review Focus

1. The shell replaces `options` while the list is open and the active option disappears → active index clamps to a valid enabled option (or none); Enter does nothing on none. Test in Task 7.
2. `value` set before remote options arrive → shows the bare value, then the label once an option with that value appears; never blank. Test in Task 8.
3. IME composition (Japanese/Chinese input) → `ssSearch` fires on `input` events as usual, but Enter during composition (`event.isComposing`) must not select. Test in Task 7.
4. `ss-input clearable` inside `ss-input-group` / with `join` → the clear button stays inside the field and the segmented seam is unchanged. Test in Task 2.
5. Card with `href` but neither a header nor `accessibility-label` → the link is named by the content region's text, never nameless. Test in Task 3.

States: `.ss-card--interactive:hover` → hover shadow/border tokens; `.ss-card--interactive:has(.ss-card__link:focus-visible)` → focus ring tokens (outline on the card).
