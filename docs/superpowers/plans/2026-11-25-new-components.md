# New components (phase 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four new components: `ss-progress`, `ss-drawer`, `ss-stepper`/`ss-step`, `ss-bento`/`ss-bento-item`.

**Architecture:** Component tokens first in ss-design-system (`tokens/components/*.json` → `--ss-<c>-*`), then the lib reads only its own tokens (`npm run lint:tokens`). Lib tests run against a committed DS copy refreshed by `npm run tokens:sync`. The drawer reuses the overlay layer (`trapFocus`, `onDismiss`) the way `ss-modal` does; stepper and bento parents read their children through `slotchange` and pass them state by props.

**Tech Stack:** Stencil 4, SCSS (`@use '../../../global/styles/control' as c;`, `c.t(component, name)`), Jest spec + Puppeteer e2e, Style Dictionary (DS).

**Spec:** `docs/superpowers/specs/2026-11-25-new-components-design.md`

## Global Constraints

- The component only shows: no data, no validation, no deciding whether a step may be entered.
- No prop depends on `data-style`. Every new color/size/duration is a component token referencing system roles (`color.*`, `space.*`, `material.*`, `shape.*`, `layout.*`, `elevation.*`, `motion.*`, `control.*`, `type.*`); new system tokens only where none fits, literals in `layout.*`.
- Existing computed-style snapshots stay unchanged.
- Encapsulation: progress, stepper, step, bento, bento-item `shadow: true`; drawer `scoped: true`.
- Accessibility asserted on the accessibility tree (`axNodeByRole`, `axNodeNamed` in `src/test/utils.ts`); cross-shadow references through `utils/a11y`.
- e2e pages via `newTestPage` + `useTokens`; `setContent` HTML starts with `<meta charset="utf-8">`; `npm test` runs one worker.
- No text-dependent widths in snapshots (CI has no Sora).
- Default copy, translatable by prop: progress `label="Progress"`; drawer `dismiss-label="Close"`; stepper `accessibility-label="Steps"`, `complete-label="Completed"`, `error-label="Error"`, `summary-label="Step {current} of {total}"`.
- SCSS is hand-aligned: never run `prettier --write` over directories with SCSS.
- `readme.md` files are generated by the build; never edit them.
- Delivery: two DS+lib PR pairs (wave 1: Tasks 1–4; wave 2: Tasks 5–8). DS PR merges and releases first; lib PR bumps `test/tokens.config.json` after `npm run tokens:sync`.

## Review Focus

1. Progress `value` larger than `max`, negative, `NaN`, or `max="0"` → clamped / treated as 100; never a fill wider than the track or a broken `aria-valuenow`. Test in Task 2.
2. A drawer opened inside a page where a dropdown is open, then closed → focus returns where it was (modal) and the dropdown's Escape still works; a non-modal drawer closed by a page button does not move focus. Test in Task 4.
3. A drawer containing an `ss-dropdown` → the dropdown's menu is placed against its trigger once the drawer is open (no transform left on the panel). Test in Task 4.
4. Steps added or removed after the stepper renders (framework re-render) → positions, derived statuses and the summary total update. Test in Task 6.
5. A bento tile with `col-span="3"` in a container where 2 columns fit → spans 2, no horizontal overflow; at one column every tile is one cell. Test in Task 7.
