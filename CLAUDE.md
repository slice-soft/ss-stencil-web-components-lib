# Working in this repository

Web Components built with Stencil, consumed as custom elements. Atoms, molecules
and organisms under `src/components/`, shared helpers under `src/utils/`.

## Read this much, and no more

| Before you… | Read | Why |
| ------------- | ------ | ----- |
| start anything | `docs/status.md` | What exists, what is next, what is blocked. Small on purpose |
| write a component | `docs/conventions.md` | The rules that are easy to get wrong here and expensive to rediscover |
| change the layer design | `MOLECULES_ARCHITECTURE.md` | The reasoning behind the molecule layer. Long, and only worth opening for the *why* |
| touch tokens | `docs/pending-token-proposals.md` | What is agreed and what is still a proposal |

`MOLECULES_ARCHITECTURE.md` is a design record, not a status board. It is written
against a specific commit and does not track what has since been built — that is
what `docs/status.md` is for. Do not update one expecting the other to follow.

## Leave the next session something to start from

Finishing a piece of work includes updating `docs/status.md`: move what you
built out of "next", record what you decided, and write down what you found that
the next person would otherwise have to find again. A session ends with no
memory of itself; that file is the only thing that carries over.

If you learned something non-obvious about Stencil, the spec DOM or the test
harness, it belongs in `docs/conventions.md`. Several entries there cost hours to
discover and minutes to read.

## Rules that bite

Full detail in `docs/conventions.md`; these are the ones worth knowing before
you write a line.

- **Coordinate children through props, not CSS.** No component exposes `::part`,
  so nothing outside a component can style into its shadow root. A wrapper that
  needs a child to look different sets a prop on it — that is what `join` is.
- **`scoped` styles do not reach slotted content.** Stencil only marks what a
  component renders itself. To style the caller's children you need `shadow` and
  `::slotted`.
- **Assert accessibility against the accessibility tree**, not against
  attributes. An `aria-*` attribute pointing across a shadow boundary looks
  correct and associates nothing. `axNodeByRole` in `src/test/utils.ts`.
- **Use `newTestPage`** from `src/test/utils.ts` in e2e, never `newE2EPage`
  directly. It raises the app-load wait the suite needs.

## Commands

```
npm test     # spec + e2e + coverage. Needs --max-workers; the script sets it
npm run lint # eslint + prettier + tsc --noEmit
npm run build
npm start    # visual harness at src/index.html, with token-set and theme switching
```

Every component has `test/<tag>.spec.tsx` and, where behaviour needs a real
browser, `test/<tag>.e2e.ts`. `readme.md` files are generated by the build —
never edit them by hand.
